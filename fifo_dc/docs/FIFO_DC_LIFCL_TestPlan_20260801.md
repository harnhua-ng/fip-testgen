## 1. Scope

This test plan covers functional, integration, system, regression, performance, usability, compatibility, smoke, sanity, and acceptance testing of the **FIFO_DC Foundation IP version 2.7.2**, scoped exclusively to the **LIFCL device family** (Lattice CrossLink-NX architecture).

### 1.1 In Scope

- All FIFO_DC functional behaviors as specified in `FIFO_DC_Functional_Spec.md`
- LIFCL-specific constraints: max memory 1,548,288 bits (18 Kb × 84 EBR blocks), max width ratio 32, FORCE_FAST_CONTROLLER feature
- Both controller implementations: `HARD_IP` (default for LIFCL) and `FABRIC`
- Both memory implementations: `EBR` and `LUT` (FABRIC only)
- All four almost-full/almost-empty assertion modes (FABRIC); static-single only (HARD_IP)
- FWFT (First-Word Fall-Through) mode
- ECC (single-bit correction, double-bit detection)
- Async and sync reset modes
- Radiant Software IP generation, synthesis (Synplify Pro and LSE), and implementation flows
- Timing constraints (`constraint.sdc`) correctness

### 1.2 Out of Scope

- Non-LIFCL device families (iCE40UP, LATG1, LAV-AT, iCE40UP — covered by separate plans)
- LFD2NX, LFCPNX, LFMXO5, UT24C, UT24CP (share T_FAMILY = LIFCL but are separate product lines)
- VHDL instantiation (RTL is Verilog only)
- Formal property verification
- Hardware-in-loop (HIL) physical board testing
- IPUG document accuracy review

### 1.3 Requirements Source

- **Primary:** `FIFO_DC_Functional_Spec.md` (reverse-engineered v2.7.2)
- **Secondary:** `Implementation/fifo_dc/metadata.xml`, `Implementation/fifo_dc/plugin/plugin.py`, `Implementation/fifo_dc/rtl/lscc_fifo_dc.v`
- **Reference:** `FPGA-IPUG-02182-1-6-FIFO-Memory-Modules-User-Guide.pdf`
- **Existing:** `FIFO_DC_LFCPNX_feature_test_spec.md` (reference for test style and structure)

## 3. Acceptance Criteria

### 3.1 Functional Criteria (FC)

| ID | Criterion |
|----|-----------|
| FC-1 | Data written when `wr_en_i=1` and `full_o=0` is stored correctly and retrieved in FIFO order. |
| FC-2 | Data read when `rd_en_i=1` and `empty_o=0` appears on `rd_data_o` with latency determined by `REGMODE`. |
| FC-3 | `full_o` asserts when exactly `WADDR_DEPTH` unread entries exist. |
| FC-4 | `full_o` deasserts within 2 `wr_clk_i` cycles of a read being detected (FABRIC); hardware-synchronizer latency for HARD_IP. |
| FC-5 | `empty_o` asserts when the read pointer equals the synchronized write pointer. |
| FC-6 | `empty_o` deasserts after a write is detected in the read domain (within 2 `rd_clk_i` cycles for FABRIC). |
| FC-7 | Writing to a full FIFO is silently discarded; no overflow status is generated. |
| FC-8 | Reading from an empty FIFO does not corrupt state; subsequent reads after data is written produce correct results. |
| FC-9 | `rst_i` clears the write pointer to 0, deasserts `full_o`, deasserts `almost_full_o`, and clears `wr_data_cnt_o`. |
| FC-10 | `rp_rst_i` sets the read pointer to the current write pointer position; `empty_o` asserts immediately. |
| FC-11 | In FWFT mode, the first valid word appears at `rd_data_o` and `empty_o` deasserts without requiring `rd_en_i`. |
| FC-12 | In FWFT mode, asserting `rd_en_i` consumes the pre-fetched word and triggers pre-fetch of the next. |
| FC-13 | ECC corrects a single-bit error in read data; `one_err_det_o` pulses for one `rd_clk_i` cycle. |
| FC-14 | ECC detects a double-bit error; `two_err_det_o` pulses for one `rd_clk_i` cycle; data is not corrected. |
| FC-15 | When ECC is disabled, `one_err_det_o` and `two_err_det_o` are permanently low. |

### 3.2 Flag Criteria (FLG)

| ID | Criterion |
|----|-----------|
| FLG-1 | `almost_full_o` asserts when occupancy ≥ `ALMOST_FULL_ASSERT_LVL` (static-single). |
| FLG-2 | `almost_full_o` deasserts when occupancy < `ALMOST_FULL_ASSERT_LVL` (static-single). |
| FLG-3 | `almost_full_o` asserts at `ASSERT_LVL` and deasserts at `DEASSERT_LVL` (static-dual hysteresis). |
| FLG-4 | `almost_full_o` responds to runtime threshold on `almost_full_th_i` (dynamic-single). |
| FLG-5 | `almost_full_o` responds to both `almost_full_th_i` and `almost_full_clr_th_i` (dynamic-dual). |
| FLG-6 | `almost_empty_o` mirrors FC criteria with occupancy comparisons reversed (all four assertion modes). |
| FLG-7 | `wr_data_cnt_o` reflects the number of valid entries in the FIFO from the write domain; accurate to ≤ 2 cycles synchronization lag. |
| FLG-8 | `rd_data_cnt_o` reflects the number of valid entries in the FIFO from the read domain; accurate to ≤ 2 cycles synchronization lag. |
| FLG-9 | All flags initialize to their post-reset state: `full_o=0`, `empty_o=1`, `almost_full_o=0`, `almost_empty_o=1` after simultaneous `rst_i` + `rp_rst_i`. |

### 3.3 LIFCL-Specific Configuration Criteria (CFG)

| ID | Criterion |
|----|-----------|
| CFG-1 | `FIFO_CONTROLLER` is visible and editable for LIFCL family with options `FABRIC` and `HARD_IP`. |
| CFG-2 | `FORCE_FAST_CONTROLLER` is visible for LIFCL (T_FAMILY = "LIFCL") and editable when `FIFO_CONTROLLER = "HARD_IP"`. |
| CFG-3 | With `FORCE_FAST_CONTROLLER=True`: max allowed `WADDR_DEPTH` and `RADDR_DEPTH` is 16383; Radiant rejects depths > 16383. |
| CFG-4 | With `FORCE_FAST_CONTROLLER=False`: max allowed depth is 65536. |
| CFG-5 | Total memory bits (`WADDR_DEPTH × WDATA_WIDTH`) must not exceed 1,548,288 bits (18 Kb × 84 blocks) for LIFCL; Radiant rejects violations. |
| CFG-6 | Memory equivalence constraint enforced: `WADDR_DEPTH × WDATA_WIDTH = RADDR_DEPTH × RDATA_WIDTH`; Radiant rejects violations. |
| CFG-7 | Width ratio `max(W,R) / min(W,R)` must be a power of 2 and ≤ 32 for LIFCL; Radiant rejects violations. |
| CFG-8 | For FABRIC controller, `WADDR_DEPTH` and `RADDR_DEPTH` must be powers of 2; Radiant rejects non-power-of-2 values. |
| CFG-9 | `IMPLEMENTATION = "LUT"` requires `WADDR_DEPTH = RADDR_DEPTH` and `WDATA_WIDTH = RDATA_WIDTH`; Radiant rejects asymmetric LUT configurations. |
| CFG-10 | `HARD_IP` controller forces `ALMOST_FULL_ASSERTION` and `ALMOST_EMPTY_ASSERTION` to `"static-single"`; no other mode is selectable. |
| CFG-11 | `HARD_IP` controller forces `ENABLE_DATA_COUNT_WR` and `ENABLE_DATA_COUNT_RD` to `"FALSE"`; `wr_data_cnt_o` and `rd_data_cnt_o` output all-zeros. |

### 3.4 Performance Criteria (PERF)
